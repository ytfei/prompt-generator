# 提示词工坊（Prompt Studio）产品需求文档

> 版本：v0.1（草案） ｜ 日期：2026-11-18 ｜ 状态：待评审
> 配套交付：`prototype/index.html` 静态原型（本次评审用）

---

## 1. 背景与痛点

用户日常运营公众号，需要高频为文章生成配图。当前直接在「即梦」等文生图工具上手写提示词，存在以下问题：

1. **考虑维度不全**：文生图涉及风格、光线、色调、构图、情绪、质感等大量维度，手写时容易遗漏，导致出图"差点意思"。
2. **表达不专业**：不熟悉生图模型偏好的提示词写法，描述口语化、不成体系，出图效果不稳定。
3. **重复劳动**：每次配图都从零写提示词，缺少可复用的配置与模板。

## 2. 产品定位

**一站式文生图提示词工作台**：通过「参数化选项 + 主题描述 + AI Agent 优化」三步，生成一条结构完整、可直接粘贴到即梦使用的高质量提示词。

**本服务不直接生图**。生图执行仍由用户在即梦完成，本产品只负责"产出靠谱的提示词"。

## 3. 目标用户与场景

- 主要用户：公众号作者（本人），非专业设计师，不写复杂代码之外的需求。
- 核心场景：写完一篇文章 → 打开本服务 → 选择风格/氛围等配置 → 简单描述主题 → 一键生成提示词 → 复制到即梦生图 → 插入文章。

## 4. 核心流程

```
选择配置（可跳过，均有默认/不限定）
        │
        ▼
填写主题描述（可选，可留空）
        │
        ▼
点击「生成」→ Agent 处理：
  ① 解析主题意图，补全画面细节
  ② 将所有选项汇总为结构化提示词
  ③ 检查维度间冲突并修正（如情绪 vs 色调）
  ④ 按创意自由度要求做迭代润色
        │
        ▼
输出最终提示词（中文为主，后续支持双语）
        │
        ▼
一键复制 → 粘贴到即梦执行生图
```

## 5. 功能需求

### M1 选项配置系统（P0）

用户通过点选 chips 完成配置。**每个维度均可不选（= 不限定，不写入提示词）**，降低使用负担。

#### 5.2 交互规则

- 单选维度：点击即选中，再点取消（回到"不限定"）。
- 用途场景联动：选择用途后自动设置推荐画幅，用户手动改画幅后以手动为准。
- 配置状态本地持久化（localStorage），刷新不丢失。
- 提供「预设模板」一键填充（见 M5）。

### M2 主题描述（P0）

- 多行文本输入，描述想表达的主题内容，如"一个年轻人在深夜的书房里写公众号文章"。
- **允许留空**：留空时仅基于选项生成氛围型提示词，并在结果中提示"补充主题可获得更精准结果"。

### M3 Agent 生成与优化（P0 原型为模拟，P1 接入真实 LLM）

点击「生成提示词」后，Agent 执行：

1. **意图解析**：理解主题描述的核心主体、动作、场景。
2. **细节补全**：根据创意自由度，补充合理的画面细节（未选择的维度由 Agent 按主题推断或留空）。
3. **冲突检查与修正**（示例规则，可持续扩充）：
   - 情绪「忧郁孤独/宁静平和」 + 色调「高饱和/霓虹撞色」 → 提示并调整为低饱和表述；
   - 用途与画幅不一致 → 自动按用途修正；
   - 负向「文字乱码」 + 文字「含标题文字」 → 在提示词中强调"文字清晰可读、无乱码"。
4. **汇总输出**：将所有维度组装为即梦友好的结构化中文提示词，形如：

```
电影感画面风格，主体：{主题描述}，背景为{背景环境}，{光线}，
{色调配色}，{构图}，{景别视角}，整体氛围{情绪}，呈现{质感}质感，
{文字留白要求}，超高细节，画质精致，画幅比例 16:9。
避免出现：水印、模糊低质量……
```

- 处理过程向用户展示分步状态（解析→补全→检查→输出），营造"迭代修复"的透明感。
- 结果区同时展示「优化说明」（Agent 做了哪些修正/补充）。

### M4 结果输出与复制（P0）

- 最终提示词以独立卡片展示，一键复制。
- 展示所选画幅比例，方便在即梦中对应设置。

### M5 预设模板（P0 提供 3 个内置，P2 开放自定义）

- 「公众号 · 科技感封面」：3D渲染 + 科幻冷感 + 霓虹撞色 + 留白放标题，2.35:1
- 「公众号 · 治愈插画」：手绘水彩 + 治愈温暖 + 黄金时刻暖调 + 留白，16:9
- 「公众号 · 写实摄影配图」：写实摄影 + 自然柔光 + 胶片复古 + 中景，3:2

### M6 历史与收藏（P1，本期不做）

- 生成历史列表、收藏常用配置为模板、提示词版本对比。

## 6. 非功能需求

- **技术栈（P1 起）**：pnpm 管理依赖；React + Vite + TypeScript；组件库待定。
- **P0 原型**：单文件 HTML（原生 JS），无构建依赖，双击浏览器打开即可评审。
- **Agent 接入（P1）**：通过 LLM API 实现真实生成与迭代，需支持自定义 API Key；P0 用本地模板引擎模拟同等交互。
- **隐私**：全部配置仅存浏览器本地，不上传。

## 7. 路线图

| 阶段 | 内容 | 状态 |
|------|------|------|
| P0 | 静态原型：选项系统 + 模拟 Agent 生成 + 复制 | 本次交付 |
| P1 | React 工程化（pnpm + Vite）；接入真实 LLM；历史记录 | 待排期 |
| P2 | 自定义模板库、双语提示词、生图结果回填（贴回即梦出图评估维度效果） | 规划中 |
| P3 | 更多平台适配（Midjourney 英文语法、Stable Diffusion 权重语法等） | 远期 |

## 8. 开放问题

1. Agent 用哪家模型 API（豆包/方舟、OpenAI 兼容接口等），Key 如何管理？
2. 是否需要输出英文提示词（即梦中文优先，其他平台英文优先）？
3. 是否建立"出图反馈闭环"：用户标记某条提示词出图好坏，用于反哺 Agent 策略？
4. 风格等维度是否允许单维度多选（如同时叠"赛博朋克+蒸汽波"）？

## 9. 验收标准（P0 原型）

- 全部 14 个维度可点选、可取消，用途联动画幅正确。
- 主题可留空，生成流程有分步动画，产出结构化提示词且可复制。
- 冲突检查至少覆盖「情绪×色调」「用途×画幅」两条规则并在优化说明中展示。
- 刷新页面配置不丢失；三个预设模板一键可用。
